# GBA Decomp (matching decomp with m2c + agbcc)

Work on pret-style decompilation projects: asm functions are drafted from machine code (m2c), judged byte-identical against the original (agbcc -O2), promoted, then migrated into `src/` behind a `make compare` (SHA1 vs baserom) gate. The repo's AGENTS.md owns project-specific commands and state layout — this skill owns the workflow order and the pitfalls that waste sessions. When they conflict, AGENTS.md wins; environment gap: AGENTS.md assumes a `fomt` wrapper on PATH, but headless environments may lack it — `python3 decomp/run.py` with `FOMT_AGENT=<name>` is the proven equivalent (same entry point `fomt` wraps).

## Sumber kebenaran (urutan prioritas)

1. `AGENTS.md` — aturan operasional repo (perintah, state, commit, hemat token).
2. `docs/decomp/POLA-DIFF.md` — katalog pola DIFF (codegen m2c→agbcc) + fungsi pembukti.
3. `docs/decomp/MIGRATE.md` — gerbang `migrate.py` (guard signature, SKIP permanen, dll).
4. Skill ini — urutan kerja & jebakan proses (jangan duplikat isi 2–3; cukup tunjuk).

Pola/temuan baru masuk ke (2) atau (3), **bukan** ke skill ini dan **bukan** ke AGENTS.md.

Realita state sekarang: progres ada di shard `decomp/state/modules/<stem>.json` +
`decomp/state/index.json` (`progress.json` hanya arsip `.bak`). Jangan menulis
angka progres/MATCH ke dokumen hidup — ambil fresh dari `fomt status` /
`git grep DECOMP-MATCHED src` setiap sesi.

Tool bantu read-only (repo `tools/scripts/`): `migrate_audit.py` (klasifikasi semua blok promoted: bisa migrasi vs alasan SKIP; `--json`), `tail_chain.py --module <stem>.s` (urutan ekor tail-only + NEXT/blocker), `audit_consistency.py` (kini juga cek status di luar enum, `i32`, dan drift promoted vs draf; `--json`/`--strict`), `migrate.py --explain` (beda signature blok vs `src/`).

## Procedure

1. **Status first.** Get fresh numbers (total / matched / failed / pending) from the project's own status entry point before touching anything; never quote numbers from memory or old session notes. Record them as the session baseline (OLD) for the close-out report.
2. **Migrate clean candidates before fixing drafts.** Dry-run the migration tool per module and act only on explicit "move" plans. A dry-run plan is a hypothesis, not proof — the real run re-verifies with baseline compare + build + target compare. A bare `Decomp N` message from this user IS the batch command: run N functions (default 20) through the standard entry point with output redirected to `/tmp`, then report per step 5 — do not ask which functions or re-explain the workflow. A request for a migration COUNT instead (`target migrasi min N`, `prioritas yang bisa migrasi`) is a different job: work only modules in `MIGRATABLE_MODULES`, fix their failed drafts, and migrate each MATCH immediately — a MATCH in a linkonce/tail-only module can never satisfy that target. Build that work queue with the repo-local `tools/scripts/migratable_failed.py` when it exists (`LIMIT=<n>` caps rows, same smallest-first order; otherwise the bundled `scripts/list_migratable_failed.py`) — the module list itself comes from `decomp.migrate.MIGRATABLE_MODULES` — and prefer compile-error notes over regalloc residuals. When one fix transfers across siblings (identical body shape), pause the size-ordered queue and sweep the whole family first: grep the module asm for the shape's distinctive line (e.g. `_call_via_r` for the vtable-call family), intersect with the `--migratable` function list and failed-not-yet-in-src status, excluding shared-epilogue fragments (ref body starts with `add sp,#N; pop` and no prologue — a shape-grep matches them but no standalone C can ever match), and apply the proven template verbatim with only pins/offsets changed — family sweeps migrate several functions per session at one fix's cost instead of scattering effort across unrelated drafts.
3. **Fix one failed draft at a time.** Read the judge note, the draft, AND the full asm of both sides together; make the narrowest edit that addresses the evidence; re-run the judge on that module only (edited drafts re-queue automatically while still failed; promoted functions never re-queue — after touching a promoted draft, sync the promoted block text to the draft by hand and prove it with the verify-mode audit before migrating); migrate on MATCH. Batches fill alphabetically by function name, so size N to reach your edited function rather than assuming N=1 judges it. When a resanitization backlog leaves hundreds of edited drafts queued ahead of yours, invoke the judge entry point directly for just that function (same pipeline, no queue, no claims, no autopush) and keep artifacts for objdiff instead of burning a giant batch. When the note shows a one-register or one-byte diff with no obvious cause, dump both complete disassemblies and compare instruction ORDER (load, spill, and call-argument sequencing) — the note truncates the context that explains it. For allocation puzzles, iterate variants locally in seconds (references/fast-local-iteration.md) and spend real judge runs only on the winner. Prefer the vendored oracles for wall diagnosis: `tools/asm-differ/diff.py -o -f <mine.o> -F <ref.o> <func>` (side-by-side with branch viz, strictly better than judge notes) and `tools/objdiff/objdiff-cli` (per-instruction DIFF_* kinds + match_percent for automation); for 1-2 byte regalloc residuals, run decomp-permuter-arm (recipe: references/permuter.md; plain-C base only, pycparser==2.20, compile.sh takes `<src.c> -o <out.o>`) — but only for ORDINARY regalloc residuals: bounded 15k+ iteration runs find no match on either parked wall below, and anything needing `__asm__` cannot even be expressed in permuter input (its parser rejects `__asm__`), so pin/anchor by hand first and permute only what remains. When note and wall disagree, extract TRUE ref bytes from the assembled module (`as -I. -Iasm` + `nm` next-symbol range) and byte-diff directly — the note's SequenceMatcher can misalign on length deltas, showing a phantom prologue diff that hides a pool/padding tail delta. Never trust the note's `mine | ref` attribution either: verify direction with raw bytes (`objdump -d` both objects) before editing, since the labels flip. Diagnostic judge invocations (verify-tagged or ad-hoc calls) never promote — only the real batch run writes promoted output, so a diagnostic MATCH must still be followed by the batch before migrating. Cap ~5 judge attempts per function: beyond that the residual is almost always a structural wall (see park rules below) — park it, regenerate the raw m2c draft (`r.draft(name)`) so the hand-edited failure stops re-queuing, record the wall in the session log, and move to the next candidate.
4. **Verify the gate after every change.** `make compare` must be green after manual src edits and after each migration. Never claim a migration without the tool's own HIJAU/OK output. `verify --module <stem>` exits non-zero when ANY function in the module fails, so read the per-function line for yours (`func_X: MATCH () | gagal 0`) instead of treating the exit code as your block's verdict. `fomt verify` is the single most expensive command in this workflow — NEVER run it unless the user asks (even project-wide at session end is off-limits; this user has said so explicitly); per-function validation is judge + `make compare`, and session close-out is `make compare` + `tools/scripts/audit_consistency.py`. Cap a session at ~3 migrations, then stop and file the log: every turn re-pays the whole conversation history, so long sessions are the dominant token cost — short sessions with a filed log beat marathon sessions. Likewise a migrate `[GAGAL]` prints an assembler warning (`use of r13 is deprecated`) that is NOT the cause — the decisive line is the C++ compile error just below it (`too few arguments`, `conflicting types`, `multiple definition`).
5. **Leave the tree clean.** Revert exploratory src edits that proved unnecessary; commit only the work's own files. Close out with OLD+DELTA numbers where OLD is the baseline recorded in step 1 and DELTA counts only this session's own migrated commits (verified via version control, e.g. `git log`/`git grep` at the session's commits) — never the requested target, and never a previous session's work re-reported as new. Count src markers with the same command at both ends; a MATCH that the migrator answers with SKIP (already in `src/`, or foreign data at the tail — migrator says `data asing ... ekor` and ref_len exceeds the code bytes) moves nothing and contributes zero to DELTA no matter how hard-won it was, so don't retry a permanent SKIP. A MATCH that only promotes — blocked by unmigrated successors — is also not committed: autopush-promote is off by default (`FOMT_AUTOPUSH_PROMOTE=0`), so `promoted/*.cc` accumulates every session's blocks; never `git add` those files wholesale (AGENTS.md rule 6) and say "promoted, not migrated" instead of implying a commit. Then file the session report to the repo's session log (same structure as the previous one: verified status, per-module table, next-session commands, SKIP decisions, manual fixes, tool fixes, standing rules) and push it — the user expects this document every session end, not just chat text. Keep chat output tiny: redirect every noisy command (batch, verify, make, git log) to /tmp/<name>.log and reply with at most ~5 lines — exit code, MATCH/DIFF counts, one status line, new MATCH names only. When diagnosing token bloat, measure output cost in bytes (`wc -c` on the log; ~4 bytes ≈ 1 token): per-command bytes are usually small, and a byte audit proves it — the dominant cost is history accumulation across turns, which is why short sessions win. Every number, MATCH and SKIP in that report must come from a tool line printed in this session: a DIFF is not "almost matching", a blocked SKIP is not a migration, and an inferred status is a hallucination the user will call out — state the residual plainly instead of implying success. Never paste logs, tooling source dumps, or full asm into chat; grep the relevant lines instead.

## Pitfalls

- **State can be stale: a "failed" draft may already be migrated in src.** Before fixing any failed draft, grep `DECOMP-MATCHED <func>` across src/*.cc; if present it is done — skip it (observed: 3 wrappers already committed while state said failed). Build the migration queue with that filter AND `tools/scripts/split_asm_sections.py --migratable asm/<mod>.s` (split modules allow mid-module moves; un-split groups are permanent SKIP).
- **The splitter's `--migratable` list is necessary but not sufficient for a migration COUNT goal.** It does not exclude code-plus-data blobs: a function whose asm block ends in long `.byte`/pool rows still SKIPs permanently at migrate time (`data asing ... menempel ekor`) even on a clean MATCH — cheap MATCHes on such blobs burn judge runs for zero migrations. Before fixing a candidate, glance at its asm tail alongside the usual in-src grep; prefer small-ref_len candidates with code-only bodies when the goal is count, and record a data-asing SKIP as permanent (never re-fix) instead of implying progress. replicate the wrapper env (`unset LD_PRELOAD; export LIBCAPSTONE_PATH=/usr/lib/aarch64-linux-gnu FOMT_AGENT=... FOMT_AGBCC/FOMT_AS/FOMT_CPP`), then `python3 -c "import decomp.run as r; r.judge(name)"` — sets status `matched` without promoting; `r.promote(name)` stages into decomp/promoted/; then real `migrate.py --module X --func <name>` (~35 s incl. baseline+target compare). **Autopush is DEFAULT-OFF since 2026-11-05 (commit a1a22373, user-mandated):** both `run.py:autopush` and `migrate.py:autopush_migrate` need `FOMT_AUTOPUSH=1`; the agent collects the session's migrations and does the commit(s) + push itself at session end, staging only the work's own files (src + state shard + drafts; never `git add -A`, never promoted/*.cc wholesale). Promoted blocks in `decomp/promoted/<stem>.cc` are the draft plus the context typedefs/externs that `promote()` auto-copies (`_expand_ctx`), with NO `extern "C" {` wrapper — the migrator adds the wrapper + section attr when inserting into src; hand-syncing the src format into the promoted file yields unbalanced braces (`syntax error at end of input`) on migrate. A `extern s32 *gX;` inside the block is auto-translated s32→i32 on insert, so it merges with an existing `extern i32 *gX;` in src. When a MATCHed callee has unused leading args, widen the definition (`s32 arg0` passthrough, zero codegen) and point the stale src extern at the same spelling — old C++ needs the repo's i32 in src, s32 only in drafts/judge.
- **vtable-call family (ldr vtable + big-offset + `_call_via_rN`):** m2c emits invalid `(*p->unk4->unkA8)->unkNNN()`. Fix = typed struct chain (Vt/H/M per function, unique suffixes) + register pins: `register Vt *vt __asm__("r1"); register u32 off __asm__("r2"); register void (*fn)(void) __asm__("r1");` — off needs `off = 0xNNN; __asm__ volatile("" : "+r"(off));` (unfenced pins fold away), fn shares vt's register (non-overlapping lives OK). Read the per-function ref homes from the asm (same shape = r1/r2 in one sibling, r2/r3 in the next); the fix transfers with only the pins and the offset changed — generate sibling drafts from `templates/vtable_call.c.tmpl` (substitute V=address, O=offset, VR/OR=pin registers). Folded variant (no `movs`+`lsls` offset build in the ref — one `ldr rN,[vreg,#0xNN]` does the whole tail): drop the off pin entirely and pin only vt to the load's home (`vt = obj->...->unk0; fn = vt->unkNN; fn();`); siblings of one shape usually share this form. When a callee takes args, give fn AND the Vt field the real arity (`void (*)(s32, s32)`) — a `void (*)(void)` fn called with args dies on `too many arguments to function`. Generate drafts with `.replace` on single-brace markers (`{V}`/`{O}`); `{{ }}` escaping is a `.format` idiom and under `.replace` lands literally in the draft as `syntax error before ')'` + `argN undeclared` on the signature line — read the written file back before judging. First try came 1 byte short (`ldr r0,[r0]` vs `ldr r1,[r0]`) — pins, not spelling, moved it. Hoist-first sub-shape: when the ref loads the vtable pointer itself into a saved register before any offset read (`ldr r4,[r0]; ldr r4,[r4,#0x24]`), pin the Vt temp to that home and derive fn through it — no off pin needed. Unsolved mirror variant, park on sight: a vtable call whose RETURN value is reused after the call (`bl; cmp r0; ldr r1,[r0,#N]` / store-then-compare) — pin iteration never moves the residual (the call result's home fights the vt pin), so stop after 2 variants and flag it for dedicated research instead of spending the cap.

- **Pola yang sudah terpecahkan — jangan diulang sebagai "wall".** Epilog `pop {r1}` (return type) dan target indirect call di `r2` (argumen ke-2 yang dibuang m2c) sudah punya resep pasti; lihat `docs/decomp/POLA-DIFF.md` §2.1–2.2. Pin `__asm__`/temp/hoisting tidak menyelesaikan keduanya.
- **Migrator gate ringkas:** tanda tangan extern harus identik string dengan `src/` (`u32` vs `s32` TIDAK ditranslasi); batch dapat menjawab MATCH untuk fungsi yang sudah ada di src → blok duplikat di `promoted/` (cek `git diff`, revert, bukan migrasi); insert ke file yang punya blok `extern "C" {` bisa merah (`syntax error before 0x…`) → sisip manual. Detail: `docs/decomp/MIGRATE.md`.
- **Never pass per-file compiler variables (`CC1`, `OLD_CC1`, `CC1PLUS`) on the make command line.** A command-line assignment beats even target-specific overrides (`build/src/m4a.o: CC1 := $(OLD_CC1)`), so a module that must compile with a different compiler silently uses the wrong one — byte size shifts a few bytes and `make compare` goes red on a +N diff that looks like a project bug, not a build invocation bug. Symptom: scattered 1–2 byte diffs (pointer literals to shifted addresses) before the shift point, cumulative +N shift after it. Fix pattern: leave the Makefile untouched and wrap the tool binary IN PLACE — rename it to `<name>.x86` and put a shell script at the original path that `exec`s the real binary under qemu; every target-specific override then works naturally. Keep secondary wrappers (e.g. `FOMT_AGBCC`) pointing at the `.x86` binary directly, never at the in-place script — qemu cannot exec a shell script and every judged function returns DIFF. `CPP` and other never-target-overridden variables are safe on the command line.
- A `promoted != draft` verify failure is fixed by VERBATIM resync, never rewriting: the check requires the draft to be a substring of the promoted file, so extract the function's contiguous block from the promoted file (its `// DECOMP-...` header line through the closing `}` at column 0, including the typedefs/externs in between — the promoted blocks carry their own context) and write it as the draft. Backup `decomp/drafts/` first; nothing hand-composed belongs in the sync.

- **Noisy commands: redirect, never dump (fomt AGENTS.md rule 7, user-enforced twice).** Any command whose output exceeds ~20 lines or 30 s — `fomt`, `verify`, `--loop`, `make`, `make compare`, `git log`, `grep -r` — runs as `<cmd> > /tmp/<name>.log 2>&1; echo "exit:$?"`, and chat gets only the exit code plus a summary (`grep -c MATCH`, `grep -E 'DIFF|ERROR|FAIL' | head -20`, `tail -5`); for a batch the canonical one-liner is `grep -E 'MATCH ->|Selesai' /tmp/fomt.log | tail -6`. Full logs stay in `/tmp`, never in the repo. AGENTS.md gets edited between sessions — re-read rule 7 instead of assuming the previous wording.
- Check ALL src variants before trusting a migration plan: some projects keep migrated code in `src/<stem>_v.c`, `src/<stem>_c.c`, or `src/<stem>_migrated.cc` alongside `src/<stem>.cc`, and planners that only check one file will propose already-migrated functions (the real run then fails with `multiple definition`). Grep every variant plus the asm (a moved function disappears from asm). Never trust a dry-run `rencana` alone — verify `func in src` yourself with grep before fixing a draft, or you will re-derive an already-migrated function.
- Explicit-reg pinning (`register T v __asm__("rN")`) forces a temp's home and defeats join-point phi-copies (proven for struct-copy src/dst and join-held pointers); verify still passes since codegen is identical. When one logical temp wants different homes in different regions (first block homes it r3, second block r2), split it into two temps — one pinned, one free — instead of fighting one temp into both homes. A store to a caller-saved pinned temp placed BEFORE a call is dead-store-eliminated (the value dies at the call, so the store vanishes and later reads go uninitialized): hoist the call result into a fresh temp first, then assign the flag after the call. It also breaks saved-register tie-break swaps: when two long-lived temps sit in adjacent saved regs swapped vs the ref (yours r6/r7, ref r7/r6, everything else identical), pin ONE temp to the ref's home and the other follows. Two pins may share one register when their lives don't overlap (method-pointer temp then call-target temp both in r2 — proven to collapse a two-instruction m-home/fn-home split into the ref's single-register reuse). If the migrator then emits literal `(None)` casts, its type lookup failed on the explicit-reg decl — conservative-skip unknown types instead of emitting garbage. LSP diagnostics on decomp drafts are not signal — the judge is the only gate (why, and pin-init side effects: references/fast-local-iteration.md).
- Manual src edits must use the repo header's types, not the judge harness's: the judge injects its own typedefs (e.g. `s32`) that don't exist in the repo headers (which may only define `i32`) — an isolated compile test of the snippet can pass while the full TU fails. Always verify with the real build.
- m2c pointer arithmetic scales by pointee size: `ptr + 8` on an 8-byte struct is +0x40, not +8 bytes — cast to a byte pointer first when the asm shows a byte offset. Conversely, `ldrb`/`strb` in asm means the field is `u8`: a draft declaring it `s32` compiles but can never match; fix the width and recompute the surrounding padding from the asm offsets. Width also dictates addressing mode: a halfword/byte field whose offset exceeds the 5-bit Thumb immediate range (0..0x1F) forces address-computation-first codegen (`adds` then `ldrh [rX]`), while a word load at a fittable offset folds into one `ldr [rN, #off]` — so when the ref computes an address your draft folds into the load (or vice versa), suspect the field width, not the expression. When two m2c fields overlap the same address at different widths (a byte field sitting inside a word field's range), keep the wider member and access the narrower one through a byte cast (`((u8 *)&word)[i]`) instead of declaring overlapping members. When one offset serves as a struct pointer at one level and a scalar at another (container `unk4` vs target halfword at the same address), declare neither — read the scalar with an explicit byte-offset load (`*(u16 *)((u8 *)x + 4)`). When the draft dereferences a field m2c declared as a plain integer (`invalid type argument of unary *`), re-type the field from the ref's load chain: two chained loads (pointer, then deref) mean the field is itself a pointer (`s32 *`), not a value. Read extra `lsl`+`lsr` pairs as a width signal in either direction: when your build zero-extends where the ref moves raw (`adds`/`mov`), the declared param or field is narrower than the original — widen it; when your build word-loads where the ref halfword-loads (`ldrh`/`strh`), narrow the field and re-pad from the asm offsets. A wrong offset in YOUR output is a width bug upstream, not an offset bug at that field: `str r0,[r4,#8]` where the ref has `[r4,#4]` means an earlier field is too wide — re-derive every field's offset from the asm (byte pair + `u8 _padN` before the next word) before touching the expression.
- Address the stack struct through a dedicated pointer variable (`p = &sp0`) so the compiler pins sp in a saved register exactly once, then load each used field into its own temp in the reference's load order before any use. Collapsing two of those temps into one (or inlining a field) changes allocation downstream and usually costs more judge runs than it saves — keep one temp per loaded field even when two of them feed the same compare.
- Old-GCC errors report where parsing surfaced, not the cause: when the flagged line looks innocent, reproduce with the preprocessed `.i` and bisect (truncate + re-append) rather than staring at the line.
- Judge notes go stale and misalign: rewritten drafts, resanitizer passes, and dry runs refresh state notes as a side effect. A note can also lag exactly one judge run behind the artifacts on disk — when a fresh same-process objdump contradicts the note, trust the objdump and re-judge once before editing. When the note's ref-side register attribution shifts between runs while the reference binary is unchanged, the differ misaligned (not your code) — dump both complete objects and compare manually, never chase the phantom register. Re-read the note for the function you are actually fixing; never work from a note quoted in an old session log. State-stored notes are also length-truncated, which hides the earliest compile errors behind a tail of warnings — when a note shows only warnings, recompile the judged inputs directly and read the full error list instead of trusting the tail.
- Only manually-edited failed drafts re-queue for judging; untouched failures are skipped by design. Don't loop the whole queue hoping for a different result — pick a function, edit it, then judge.
- Manual edits survive only until the NEXT judge run: `resanitize_stale` protects a draft while its mtime is newer than `judged_mtime`, and judging bumps `judged_mtime` past the edit — so the following batch regenerates that draft from raw m2c and the fix silently vanishes (observed: a fixed draft came back one batch later with its original `request for member ... not a structure` error). Keep the edit and its judge run in the SAME shell invocation, and when a later batch reports a function you already fixed with its ORIGINAL m2c error, re-apply the edit instead of diagnosing it again. The state's `sanitize_checked_v` (against the current sanitize version) is the flag that marks a draft as a sanitize fixpoint, and `_looks_sanitized` scans for raw m2c markers (`extern ?`, `? *`, `? temp`, `? arg`) when deciding to regenerate.
- The runner's positional args are `[N] [module ...]`: `status` and `decomp` are special-cased (`status` = progress only, `decomp` = alias for `[N]`; covered by `tools/tests/test_cli.py`), and `--help` prints usage without running a batch; any OTHER non-digit token becomes a MODULE filter. `python3 decomp/run.py func_080222A8` therefore scans a module named `func_...` that does not exist and prints `antrean habis` with every function skipped as `modul-lain` — not an empty queue. To judge one edited draft, pass the size AND the real module file (`python3 decomp/run.py 1 code_entities.s`); status numbers in that same output come from the full state and are still valid.
- Write drafts and promoted blocks with the JUDGE's type names (`s32`), never the repo's (`i32`): the harness defines only its own typedefs, and the verify audit compiles the promoted block without repo headers, so an `i32` there fails to compile while the identical `s32` passes — the migration tool translates `s32`→`i32` on the way into `src/`. The harness's generated `common.h` also predefines common helper type names (`Vtbl`, `Pair`, …): a draft that typedefs one of those names fails with `common.h:14: syntax error before 'Vtbl'` even though the draft itself is valid C. Suffix custom typedefs with the function's address (`Vtbl860`, `Pair860`) — zero codegen impact and the collision disappears.
- **Write C drafts with file tools, never shell heredocs.** The terminal layer refuses any command containing a single `&` (backgrounding guard) — and C drafts are full of address-of and bitwise-`&`, so every heredoc carrying one is rejected before it runs. Use the file write/patch tools for all draft content; reserve the shell for judge/migrate/verify invocations only. `&&` command chains and `python3 -c` one-liners contain no single `&` and still run, so the edit+judge-same-invocation rule keeps working via `&&`-joined shell commands.
- If a migration turns compare RED inside functions you never touched, stop editing your block — the migrator rewrote a shared extern declaration on the way in (e.g. normalizing an allocator's return type to a project-wide canonical), and the old compiler resolves that first-seen declaration at every old call site, so untouched neighbors fail. Diff the tool's staged output against the pre-migration tree to confirm, then fix the tool to follow the module's established convention (never force-canonicalize a live module); the matched draft itself is innocent.
- A migrated function must reuse the extern signatures already established in `src/` for shared globals and callees: the migration guard compares declaration strings and blocks on any mismatch. Conform the NEW block to the existing convention (pointer/int casts at call sites are codegen-neutral); when the migration itself changes a signature an already-migrated src caller uses, cast that caller to the NEW types FIRST while the old extern still accepts it (still green), then migrate — the migrator reverts on any intermediate red, so caller-first, migrate-second. After editing a promoted block, prove it with the verify-mode audit, since the normal judge only reads drafts and never re-queues promoted functions. The same applies to globals: when the new block declares `void *gX` but `src/` already has `i32 gX`, the build dies with `conflicting types for 'void * gX'` — change the block to `extern s32 gX;` and cast at the use (`(u8 *)gX + 0x36C`), then re-verify the promoted block (`verify --module <stem>`) and migrate; editing the draft alone changes nothing because a matched function never re-queues.
- Functions sharing an identical diff signature in one module usually share one structural cause: diagnose one fully against both full disassemblies, then transfer the proven fix to the siblings before spending judge runs on each separately.
- Match the reference's evaluation ORDER, not just its values: hoist a subexpression into a named temp assigned at the exact point the reference computes it (a shifted arg, a hoisted offset); the temp's home then pins downstream allocation. When the compiler reassociates a nested sum (`t1 + (t0 + C)` emitted as `(t1 + C) + t0`), hoist the INNER sum into its own temp (`tin = t0 + C`) so the emitted order is forced. Chained stores (`a = b = v`) emit right-to-left, so split them into separate statements in the reference's store order when the note shows swapped consecutive stores. Conversely, a temp that must NOT exist (CSE across calls is impossible, so separate loads stay separate) should be written as repeated field/cast accesses.
- Force copy-then-op stores with their own temp, and op targets with operand order or in-place splits: when the ref copies a value to a scratch reg before operating (`adds r0,r4` then `ands r0,r3`), assign the store value to a dedicated temp in a separate statement (`t2 = seven & b`) — folding it into the consuming expression lets the compiler operate in place and the copy disappears. When the ref's `orrs`/`ands` targets the other operand's register than yours, swap the operand order — the target follows the first-written side (proven for both `|` and `&`). To force multi-step codegen directly into a pinned home instead of scratch-then-move, split the expression into separate read-modify-write statements on the pinned temp (`f = v<<30; f >>= 30; f += 1; f &= 3`). To force a literal into an already-pinned register, assign it through the pinned temp (`n = 3; f &= n`) rather than a bare constant. To force operation ORDER between two independent statements the scheduler wants to swap (ref loads before it subtracts, yours subtracts first), insert an empty volatile fence on the loaded temp (`__asm__ volatile("" : "+r"(cur))`) — zero codegen, scheduling barrier both ways. One fence also keeps a whole dependent chain opaque: a mask temp negated once under fence stays unknown through subsequent in-place subs, so the chain emits instead of folding to one constant. Match shift SIGNEDNESS through operand types, not casts at the use: ref `lsrs` needs an unsigned operand (`u32`), ref `asrs` a signed one — a cast wrapped around the shift itself is a no-op the scheduler ignores. The same signedness rule decides byte-loaded compares: when the ref emits the unsigned branch (`bhi` for `x > C` on an `ldrb`-loaded value), declare the loaded value `u32` so yours zero-extends instead of sign-testing (`bgt`); if two spellings still differ by branch kind on provably-narrow data, park — the compiler range-proves the fold and no spelling changes it.
- When two stack scalars land in swapped slots regardless of declaration order, assignment order, or which variable holds which value, stop reordering and declare one array (`u32 st[2]`): slot order then follows the index, and `&st[i]` takes emit in written order.
- When the ref prologue copies one argument register into another (`adds r0,r1,#0`), or its first use reads `r1`/`r2` directly while the draft's body uses `arg0`, m2c dropped a leading unused argument — confirm the true arity from the caller's `bl` setup (r0..r3/`[sp]`/`[sp+4]`) and add the unused leading param; three siblings sharing the same `cmp r1,#N` body take the same fix verbatim. m2c also drops the evidence of which register held the arg: when your output compares `cmp r0` where the ref compares `cmp r1` (a `cmp r1,#1` in the ref while your draft uses `arg0`, i.e. `adds r0,r1,#0` never emitted), the function takes TWO leading args and the compared value is the SECOND (`s32 arg0, s32 arg1` with `if (arg1 == 1)`) — adding only one leading param keeps the one-byte `cmp r0` residual.
- A trio of identical single-byte `cmp r1,#N` siblings sharing that body shape ALL take the two-leading-args fix — cheap MATCHes, judge each once and migrate together.
- Match the reference's code SHAPE, not just its logic: emit hoisted temps in the order the reference loads them (a swapped pair scrambles allocation downstream), and keep branch polarity identical (`== 0` assembles to `beq`, `!= 0` to `bne`) — logically equivalent sources routinely differ by one byte. A goto loop versus the same for loop are different shapes: if the ref has a branch-to-condition plus an inline pool between the jump and the body, the source is a for, and no goto spelling will match the pool placement.
- Old GCC may reorder `switch` cases (typically ascending) even when the reference checks them in source order: if the compare sequence doesn't match, rewrite the dispatch as an `if`/`else if` chain, which preserves the written order.
- agbcc `-fhex-asm` prints `mov`/`orr`/`and` where real asm shows `movs`/`orrs`/`ands`: the missing `-s` is NOTATIONAL (same bytes) — don't chase S-bit "diffs" between pseudo-asm and real asm; chase only what the byte compare reports.
- Known regalloc walls (park on sight, don't iterate blind): (a) a first-loaded temp the reference homes one register higher than every variant you try (assignment order, extra temps, and hoisting don't move it — the tie-break is elsewhere); (f) a provably-dead unsigned check the ref still emits (`cmp r5,#0; bcc` — unsigned-below-zero can never be true): every spelling folds it away (unsigned variants fold silently, signed variants emit `blt` instead), so park once two spellings confirm the fold rather than sweeping spellings; (b) a `-0x80` mask the reference materializes via `movs`+`rsbs` while agbcc folds every `(x & -0x80)` spelling to `(x & 0x80)` for byte-known `x` — BROKEN via `register s32 neg __asm__("r0")` + `neg = -0x80; __asm__ volatile("" : "+r"(neg));` + compound `neg &= x; neg |= 1;` (forces reg-reg AND with result in the mask's home; precedent `func_080D3870` proves `__asm__` survives to src). The same movs+negs barrier generalizes to any small negated constant the ref emits as `movs rN,#C` + `negs rN,rN` while agbcc constant-folds `0 - C` into one `movs rN,#-C` (proven for 0x40): assign the constant to the pinned temp, fence it with the empty volatile `"+r"` barrier, then negate. When the ref ALSO loads the operand before materializing the mask (`ldrb r1,[r4,#4]; movs r0,#0x10; rsbs r0,r0,#0; ands r0,r1`), load it into a plain temp first (`v = field;` ahead of the pinned sequence) — pinning the mask alone reorders the load after `movs`/`neg` and leaves a stable 2-byte diff. (c) [FIXED — not a wall] an epilogue `pop {r0}` vs `pop {r1}` with otherwise byte-identical bodies: the ref's `pop {r1}; bx r1` means the function RETURNS a value — declare it `s32` and `return` the last call (zero other change). Variant: ref tail `ldr r1,[r0,#N]; asrs r0,r1,#0x10` = `s32 a = 0;` assigned AFTER the call, then `return a >> 16;` (initializing before the call spills to r4 + `push {r4}`); (d) scheduler lottery: the ref loads a literal pool AFTER the branch while agbcc hoists it before the compare, or the ref keeps identical if/else tails inline while agbcc cross-jumps them into one shared tail — when only pool timing or merged-vs-inline tails differ and two structural rewrites (direct stores per branch, ternary) don't move it, park; the same park applies when the only residual is tail padding (`movs r0,r0` in the ref vs `.byte 0xff,0xff` in yours, body lengths 2 bytes apart) — that is alignment fill, not code you can write your way out of; (e) a synthesized large-offset constant homed in a different scratch register than the ref (`movs r1,#0x8c` vs `movs r3,#0x8c` with otherwise identical bodies — field and literal spellings synthesize the same constant, and off-temps, address-temps, and explicit-reg pins only relocate the residual instead of removing it, so park once two variants merely move the diff); (g) a stack-arg call whose ref saves a pinned register in the prologue that agbcc refuses to save (`push {r4,r5,r6,r7,lr}` + `sub sp,#8` in the ref vs `push {r4,r5,r6,lr}` in yours with off pinned r7) — pins force a temp's HOME but do not add to agbcc's save-set, so two pin variants (plain temps vs pinned arg temps) not closing the prologue diff mean park. (h) a loop-invariant mask copy the ref emits inside a do-while as `adds r0,r3,#0` sandwiched between the value load and `ands r0,r1` — agbcc commutes the AND and folds it to one in-place `and rd,rm` with the mask's home; every forcing attempt (result pin sharing r0, fences on mask/copy/value, operand swap, `t = *reg4` reorder, block-scoped pin) either keeps the fold or reorders worse, so park once two shapes confirm (and regenerate the raw m2c draft — see below). After parking, regenerate the raw m2c draft (`r.draft(name)`) so the hand-edited failed draft does not re-queue every future batch, and record the wall in the session log. If the migrator then SKIPs on a stale src extern (`i32 (i32)` vs definition), unify manually: point the stale extern + its call-site at the definition's signature (with `void *`/concrete casts, codegen-neutral) and pre-place the block's typedef verbatim in MIGRATED TYPES so the auto-rename dedupes it — then migrate and let `compare` prove the edited neighbor still matches. The guard compares declaration STRINGS, so unifying to `void *` can still refuse with the definition side reported as `GenObj *`; when that happens, rewrite the draft AND the promoted block to the plain `void *` spelling (drop the struct view, access fields via `(u8 *)arg0 + off`) and re-run the verify audit — re-typing the extern to the struct is the wrong direction and only moves the mismatch.
- Never chain an explicit deref-cast into a member access (`m = *(T **)t; ... m->field`): agbcc re-derives through the deref and emits a double load (`[m]`, then `[+off]`) where one `[m, #off]` belongs — the same access in isolation compiles correctly, so the shape, not the field, is at fault. Spell it as field access on a plain temp (`m = (T *)(t->field0)` with a pointer field at offset 0) and prove the collapse locally before spending a judge run.
- Read `stm r0!,{rX}` as post-increment store idiom: the source is `*p++ = v` with the bumped pointer reused directly (call arg) and the original kept in a saved-reg copy (`a = (T *)p` first). Recomputing the bumped address with byte arithmetic after a plain store emits an extra `adds` — restructure to the increment idiom instead. The INVERSE fusion also bites: a store followed by an in-place pointer bump (`*p = v; p = (T *)((u8 *)p + N); *p = v2;`) fuses into `stmia rN!,{...}` / a folded `[rN,#N]` store when the ref emits `str; adds rN,#N; strh` as separate instructions — block the fusion with an empty-volatile fence on the pointer between the store and the bump, or bump through a differently-typed pointer variable (`volatile u16 *` after a `volatile u32 *` store) so the two stores can't coalesce.
- **MMIO/register-poke family (literal-pool `0x04xxxxxx` addresses, ≤1 `bl`, ref_len 40–130) is a recurring cheap-win class** — filter the failed queue for it before grinding bigger functions. Recipe: type each register as a `volatile u32 *`/`u16 *` (volatile = the compiler may not eliminate the dead address materializations the ref still emits, e.g. `(void)*(volatile u32 *)0x04000150;` reproduces a dead `ldr r0,=0x150; ldr r0,[r0]` pair); pin long-lived pointers and the store-value temp to the ref's homes (`register volatile u32 *dst __asm__("r1"); register u32 val __asm__("r0");`); a pointer compare against the raw incoming register (`cmp r3,#0`) means that param is `s32`, not `s16` (the ref never truncates it). Constants the ref builds as `movs r2,#C; lsls r2,#N` fold back into literal-pool loads unless you pin a scratch reg for the constant and fence BETWEEN the materialize and the shift (`c = 0x80; fence; c = c << 8;`), then copy to the pinned store-value temp (`val = c;`). Emit statements in the ref's order — the ref materializes the destination ADDRESS register before building the constant, so assign the address pointer first and judge the diff note against that order. A large struct offset the ref materializes from the pool (`ldr rN,=0xNNNN; adds`) is reproduced by pinning the offset to the ref's scratch register with a fence (`register u32 off __asm__("r3"); off = 0x1054; fence; ...((u8 *)arg0 + off)`).
- A promoted block declaring `extern void *gX;` beside src's existing `extern i32 *gX;` dies with `conflicting types` — the migrator's s32→i32 auto-translate covers the `s32` spelling only, not `void *`. Spell the promoted block's extern `i32 *gX;` and cast at the use (`gp = (s32 **)&gUnk_0300041C;`), codegen-neutral; edit the PROMOTED block, not the draft (a matched function never re-queues).
- Migration is strictly last-to-first PER MODULE, not just for linkonce: the gate refuses any MATCH that still has unmigrated successors in its module (`bukan fungsi terakhir di <module>.s (N penerus belum pindah, dilewati)`). Such a MATCH still counts toward `berhasil` but moves nothing — record it as blocked, do not re-fix the draft, and do not report it as a migration. To unblock, migrate the module's tail functions first (or defer the module); count the successor chain before starting and, if it exceeds the session, say so instead of picking mid-module MATCHes. Linkonce is only the worst case: failed functions at a module's tail block everything behind them. Don't grind the blocked queue — fix the tail blockers first (e.g. func_080E54F0, func_080E55B0, func_080E5664 once blocked ~128 linkonce candidates, with E5664 last so it migrates the moment it promotes). Count the sequential chain to first payoff before starting — every blocker must land in order before anything behind them unlocks — and if the chain exceeds the session, explicitly defer the module instead of re-picking blocked candidates.
- **Tiny drafts are often fragments, not functions.** A ≤6-line draft in a migratable module whose ref body has no prologue (starts `add sp, #N; pop {...}` or `ldm r0!, {...}`), ends by branching into another function's local label (`b .L08031F0E`), or whose draft calls a literal `0(...)` / `? 0(...)`, is a shared-epilogue tail of a larger function — no standalone C can ever match it. Detect this before spending judge runs (check the ref's first and last instructions, not the note) and skip to a real function whose ref starts with a prologue and returns normally. When picking drafts for a migration target, sort the migratable module's failed drafts by size, drop fragments, and prefer notes that are compile errors (type/param fixes) over regalloc residuals.
- m2c misorders zero-then-read: `*p = 0; x = *p` always yields zero — when the ref reads `*p` BEFORE zeroing, introduce a temp (`t = *p; *p = 0; x = t`); the temp also pins the load early, which is frequently the entire remaining diff. When several siblings share this shape, fix one and transfer verbatim.
- When sibling callers disagree on an unmigrated callee's signature, settle the canonical from codegen evidence, not first-seen: an `lsl`+`lsr` canonicalization on a caller's argument PROVES a narrow parameter, while constant arguments are width-agnostic (a const fits either declaration, so a const-caller matching under the wrong width proves nothing). Fix the stale src extern to the proven signature — const-arg callers emit identical code, so compare stays green — sync the drafts' externs, re-verify each, then migrate. When the proven signature is WIDER than an already-migrated src definition (ref shows callers setting argument registers the definition ignores), widen the src definition with unused trailing params instead — same codegen, compare stays green — then migrate the new caller.
- m2c mis-emits calls to callees that aren't migrated yet: when the judge log reports `too few arguments` or `incompatible pointer type` for a callee, distrust the draft's extern decl AND every call site. Take the callee's true signature from its own draft (or `src/` if migrated), then reconstruct each call from the ref asm: dump ~14 lines above every `bl <callee>` and read the six arg slots (r0, r1, r2, r3, `[sp]`, `[sp+4]`) back to C values — caller codegen depends only on arity and 4-byte arg sizes, so fix the count first and don't fuss pointer spellings. m2c's `?` placeholder params default to `s32` unless the ref canonicalizes that argument (`lsl`+`lsr` on entry means a narrow type). A bare `?` in the function's OWN parameter list (not a call site) is not valid C: old GCC errors `argN undeclared` on the body lines, so replace it with a concrete type proven by the asm (pointer deref → `void *`, `lsl`+`lsr` → narrow). Then count `bl`s vs draft call sites: if the draft has MORE, m2c split one instruction into two (two setup paths converging on a single `bl`) and the draft can never match as written — restructure to one call with path-dependent (phi) args. Chained variant: the arg is the PREVIOUS call's result still sitting in r0 (m2c emits a bare call with the arg lost). Hoist to a temp or assign inside || so the value stays in r0 on every path. When the ref jumps to a shared epilogue immediately after a `bl` but the draft falls through into following code, the draft is missing a goto — add an explicit jump to the shared end label; the cross-jumped tail only merges when every path arrives at it by branch. When the ref leaves an argument register untouched before the `bl` (no setup for r3/`[sp]`), the callee takes that slot as a real parameter — add a passthrough param and forward the incoming value (never assigned: zero codegen, silences `too few arguments`, which old GCC errors on). The mirror case — the callee is ALREADY migrated in `src/` with MORE params than this caller's ref sets (the callee's body genuinely uses them, so it cannot be narrowed) — is fixed at the CALL, not the signature: cast the call to a narrow function-pointer type, `((void (*)(s32))func_08034BFC)(arg0->unk10);`. The cast emits exactly the ref's `ldr r0,[r0,#0x10]; cmp; beq; bl` (no extra register setup) and satisfies the C++ prototype the migration build enforces; leaving the bare call matches the judge but fails `make` in `src/` with `too few arguments`. When the judge reports `void value not ignored` on a shifted virtual call (`((void (*)(void *,...))(p->unkX))(a) << 0x18`), m2c typed a value-returning callee as void — change that call's cast to `s32 (*)(void *,...)`. The same fix applies when the result is used WITHOUT a shift (`t = call(...)`, `if (call(...))`): any call whose return value is read needs the value-returning cast. Only bare statement-calls whose result is discarded stay `void (*)`.
